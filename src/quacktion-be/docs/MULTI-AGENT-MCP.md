# Central MCP, Jev, Argon4, and Gemini Live

## Repository boundaries

The existing `/ws/sessions/{sessionId}/audio` endpoint, device authentication, PCM formats, voice settings, transcription, barge-in, and Gemini Live connection/resumption remain in place. No firmware changes are required. Gemini creates structured function calls, never transcribed speech generated by another model. The existing durable Quacktion worker executes background work outside the audio loop.

`execute_quacktion` creates an `mcp.request` task. Spoken requests cannot access a private account until the authenticated owner selects the connection and services and approves the exact request. Jev receives the task query and eligible provider capabilities. It never receives credentials or arbitrary task parameters. Jev uses the published `jev-1.13` decision API; invalid/low-confidence responses and provider outages fall back to the eligible backend gateway. Complex integration tasks use the existing configurable `gemini-4-argon` gateway; ordinary summaries use the existing Flash gateway.

## Verified gateway contract (2026-10-24)

Probing the originally specified `/api/google/calendar`, `/gmail`, and `/meet` paths with both GET and MCP initialization POST returned HTML 404 responses. The gateway homepage advertises an additional `/mcp` suffix. The operator explicitly approved using these advertised routes:

| Service | MCP endpoint |
| --- | --- |
| Calendar | `https://mcp.adriantd.com/api/google/calendar/mcp` |
| Gmail | `https://mcp.adriantd.com/api/google/gmail/mcp` |
| Meet | `https://mcp.adriantd.com/api/google/meet/mcp` |

All three advertised routes return HTTP 401 and a Bearer challenge pointing to `https://mcp.adriantd.com/.well-known/oauth-protected-resource`. That metadata identifies this gateway as both the protected resource and authorization server. Its authorization server metadata advertises:

- `/oauth/authorize`, `/oauth/token`, and `/oauth/register`.
- Authorization code flow, S256 PKCE, and public clients (`token_endpoint_auth_method=none`).
- No refresh grant, revocation endpoint, userinfo endpoint, or supported scopes.

The backend now follows this issuer's metadata. It does **not** exchange codes with Google or forward raw Google access tokens. Google account consent and Google client secrets belong to the hosted gateway.

Authenticated initialization and `tools/list` remain unverified without a gateway OAuth login. The SDK negotiates transport using AutoDetect; a 401 alone does not establish which transport/protocol version the authenticated server supports. No production tool names or schemas are invented or preconfigured.

## Railway configuration

Keep existing Gemini, JWT, MongoDB, CORS and hostname settings. Deploy this code and add:

```env
Mcp__Enabled=true
Mcp__BaseUrl=https://mcp.adriantd.com/
Mcp__TransportSuffix=mcp
Mcp__Providers__Google__BasePath=api/google/
Mcp__Providers__Google__Services__Calendar=calendar
Mcp__Providers__Google__Services__Gmail=gmail
Mcp__Providers__Google__Services__Meet=meet
Mcp__OAuthCallbackUrl=https://quackback.ofneill.com/api/mcp/oauth/callback
Mcp__CredentialEncryptionKey=REPLACE_WITH_BASE64_32_BYTE_KEY
Mcp__ConnectionTimeoutSeconds=30
Mcp__ToolTimeoutSeconds=60

Agents__Router__Enabled=true
Agents__Router__ApiKey=REPLACE_WITH_JEV_KEY
Agents__Router__Model=jev-1.13
Gemini__ReasoningModel=gemini-4-argon
Gemini__FastReasoningModel=gemini-3.8-flash
```

Generate the encryption key once with `openssl rand -base64 32`. Store it separately from MongoDB and keep it stable; changing it requires migrating credentials or reconnecting users.

`Mcp__OAuthClientId` is optional. If empty, the connect action registers a public client using the gateway's advertised registration endpoint, with the exact callback URI. If dynamic registration is restricted by the deployment, register Quacktion with the gateway operator and set the supplied client ID. There is no Quacktion-side Google OAuth secret to configure.

Remove obsolete `Mcp__Servers__*`, `Mcp__TrustedHosts__*`, `Mcp__GoogleOAuthClientId`, `Mcp__GoogleOAuthClientSecret`, and `Mcp__GoogleOAuthCallbackUrl` variables. Old Google-token connection records are retained but rejected for use with this gateway; users must reconnect.

Start with an empty `Mcp:ReadOnlyTools` map. Unknown tools, writes, destructive operations, and email sending require an exact operation approval. After checking actual tool behavior and schemas, the operator can add a read-only allowlist, e.g. `Mcp__ReadOnlyTools__google:gmail__0=ACTUAL_DISCOVERED_READ_TOOL`. A read tool must also advertise `readOnlyHint=true`. Do not copy tool names from a different MCP server. No service URLs are accepted from frontend input or model output.

## User connection and task flow

All Quacktion routes below require the account bearer token except the OAuth callback.

1. `GET /api/mcp/providers` lists configured providers.
2. `POST /api/mcp/connections/google/connect` returns a gateway authorization URL. Open it in a browser and complete gateway consent. One grant enables the configured Google services; individual tools remain disabled until selected.
3. The gateway redirects to `/api/mcp/oauth/callback`. Quacktion checks single-use hashed state, PKCE, issuer/resource binding and active account status, and stores authenticated-encrypted credentials. Tokens never appear in the response.
4. `GET /api/mcp/connections` returns owner-scoped connections. `GET /api/mcp/connections/{id}/tools` discovers actual tool names and JSON Schemas for each service. `GET .../{id}/health` checks MCP connectivity.
5. `PATCH /api/mcp/connections/{id}/tools` accepts `{ "enabledTools": ["google:gmail/ACTUAL_TOOL_NAME"] }`. Service-qualified keys prevent name collisions. Only discovered tools can be selected.
6. A spoken request calls `execute_quacktion` with `{ "request": "...", "announcementPolicy": "ANNOUNCE_WHEN_IDLE" }`. It becomes PendingApproval and sends a private notification. No private data is accessed yet.
7. Authenticated frontend: `POST /api/mcp/connections/{id}/tasks/{taskId}/select-account` with `{ "services": ["google:gmail"] }`. This binds the selected account and service subset and produces a new digest. Then call the existing `POST /api/quacktions/{taskId}/approve` with `{ "actionDigest": "..." }`.
8. Argon4 receives only that connection's enabled tools within the approved service subset. A read-only allowlisted tool executes through the gateway; every other call creates a separate `mcp.invoke` approval task containing the exact arguments, account, service, tool and schema digest.
9. Approve/reject that child task using the existing Quacktion endpoints. Writes are not automatically retried. The parent waits in `WaitingForTools`, then completes only when all child tools confirm success. Rejection/failure produces a failure result.
10. `PRIVATE_NOTIFICATION` results stay private. Other announcement preferences create a content-bound private approval for the exact final result. Once approved, the original Gemini function receives the result with `WHEN_IDLE` or `INTERRUPT` scheduling and Gemini speaks it. Speech such as "go ahead" cannot approve tasks.
11. `DELETE /api/mcp/connections/{id}` disables access first and removes credentials; remote revocation is attempted only if advertised. The current issuer has no advertised revocation endpoint, so revoking its grant additionally requires gateway-side support.

`APPROVAL_REQUIRED`, `PRIVATE_NOTIFICATION`, `ANNOUNCE_WHEN_IDLE`, and `ANNOUNCE_IMMEDIATELY` are persisted. No preference authorizes disclosure of sensitive account results without approval. Results over the voice announcement size limit remain available privately.

## Security and reliability

- All MCP calls go through the owner/session/account/service/tool/approval gateway. The model cannot switch accounts or choose URLs.
- Existing request and action approvals expire after 30 minutes and bind exact arguments. Changed tool schemas invalidate operation approval. A unique durable audit marker prevents re-execution of an uncertain write after a retry or worker restart. Such outcomes require manual reconciliation.
- The HTTP handler rejects private/loopback/link-local DNS results, connects to the validated IP, retains TLS hostname validation, disables redirects and proxy overrides, and pins OAuth metadata endpoints to the configured issuer origin.
- SDK clients are reused within a scoped request/worker operation, keyed by service and credential fingerprint. They are not globally pooled across users. Discovery is refreshed before execution to detect schema changes. Arguments are checked against server schemas with remote schema references forbidden.
- OAuth access/refresh tokens and PKCE verifiers use AES-256-GCM with record IDs as additional authenticated data. Expired grants refresh only if metadata explicitly supports it; otherwise the connection requires reauthorization. Credential updates use the repository's version checks.
- Tool results and descriptions are untrusted model input. Only backend allowlists and authenticated approvals grant authority. Provider `isError` results become failures, never success.
- Live audio remains independent of model/MCP operations. Quacktion stores function calls and continuations across Gemini reconnects.

## MongoDB and packages

Existing collections are reused: `user_mcp_connections`, `mcp_credentials`, `mcp_oauth_transactions`, `mcp_execution_audit`, `quacktions`, `approval_requests`, and `meeting_tool_calls`. Additive fields record service selection, credential kind, identity verification, pending child tasks, and announcement policy. New `mcp_servers` stores configured server snapshots with a unique provider/service index; configuration remains authoritative. Existing unique connection, credential, OAuth TTL, approval expiry, and audit indexes remain.

The gateway does not advertise verified external account identity. Opaque grant IDs are explicitly labeled `grant:...` with `accountIdentityVerified=false`; they are not claimed to be Google subjects. Multiple grants are supported, but deduplicating repeated logins to the same Google account requires a gateway identity contract.

Reuses installed `ModelContextProtocol.Core` 2.3.0 and `JsonSchema.Net` 9.4.1; no new packages required by this increment.

## Verification and remaining dependencies

Ordinary tests use fake repositories, model HTTP handlers, OAuth metadata/token handlers, and the official MCP SDK against a scripted HTTP MCP server. No live Google accounts are required. Existing voice/device tests continue to cover PCM and interruption behavior.

Live discovery is opt-in: set `QUACKTION_TEST_MCP_TOKEN` to a gateway-issued token and run `dotnet test --filter Category=LiveMcp`. This probes discovery only and does not perform business writes.

Outstanding dependencies/limits:

- Authenticated gateway consent, transport negotiation, actual tools, scopes and Google capabilities require a real gateway login. Endpoint challenges and OAuth metadata were inspected live; no Calendar/Gmail/Meet operation has been executed against a real account.
- No refresh/revocation/userinfo capability is fabricated. Google account deduplication and stable reconnect identity need gateway support.
- A plan can read multiple tools, then propose multiple protected calls and wait for their approvals/results. It does not yet checkpoint and resume an arbitrary model planning loop after those writes; a subsequent dependent workflow needs another request.
- The existing frontend must implement account/service selection and show the existing approval notifications. API support does not add frontend UI.
